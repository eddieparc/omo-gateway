## Active-path proof and applicability

The active executable constructs **OmoBackend**, not a legacy in-process LLM runner (`src/main.rs:1237-1260`). It installs DiscordEgress into that backend's SharedDispatcher (`main.rs:1277-1281`); SharedDispatcher forwards actions unchanged (`main.rs:289-296`). OMO final agent text and its separate badge become `OutboundAction::Stream` through B::emit_chunk (`B:330-342,627-661`), then R::dispatch -> R::stream (`R:2199-2201,1842-1907`). That path performs table conversion and final edits, **not** silence/reasoning/media/footer processing. These construction and final-delivery locations were reread during the final audit pass.

Consequently D01/D05/D09/D16/D17 apply to actual interactive OMO delivery. D06 distinguishes active Stream's missing dead-target guard from SendMessage's faulty classification (actor errors and scheduled sends use the latter); it does not claim normal OMO finals use SendMessage. D07's missing MEDIA interpretation is an **unsupported optional protocol**, not a broken UploadFile call from OMO. D08 is **latent**: explicit UploadFile can reach the malformed voice builder, but no active OMO producer was found. D11 is **unsupported optional gateway STT**: main.rs:1373 installs a downloader without an STT provider; a detached SpeechToText trait cannot prove live transcription. D10 is a broken exposed configuration toggle, not proof that the optional footer was ever supported end-to-end. D27 certifies transport primitives only, explicitly not active OMO approval integration. Slash-only paths such as D13 run directly in Poise and legitimately bypass OmoBackend.

No optional VC/TTS, non-Discord platform, or independent agent product is proposed as required corrective work. Optional implementation scenarios below are acceptance contracts only if that feature is separately selected.

## Feature parity versus defects

The 18 registered Rust commands are model/reset/stop/status/tools/skill/skills/memory/cron/steer/undo/retry/compress/title/thread/deny/yolo/pair. Hermes H:4937-5168 also registers new/reasoning/personality/sethome/resume/usage/help/insights/reload-mcp/reload-skills/voice/update/restart/approve/queue/background and registry-driven additions. These are not all defects: resume/new session rotation and reasoning display conflict with dedicated-session/final-only invariants; independent intelligence/personality/background operations belong to the daemon; administrative update/restart must not be blindly exposed. Help/usage/model-inspection, explicit queue alias, channel prompt/skill bindings and optional VC/TTS are **unimplemented feature parity**, not falsely certified by `test_all_commands_count`. Existing `/title` renames Discord thread only, not Hermes named-session titles. `/cron` currently only lists (C:491-541); expanded cron control belongs to cron owner.
