### DS01 - Slow restart loops evade the existing auto-resume breaker (runtime defect)

- **Upstream change:** `gateway/restart_loop_guard.py:26-34,56-88,98-114` replaces the 60s sliding window with an unbroken inter-boot chain, default maximum gap 300s. Installed `gateway/restart_loop_guard.py:72-88` used the short window. This is not runtime R06 (daemon supervisor respawn budget), nor a duplicate of PRESENT runtime R05 / sessions S03.
- **Rust proof:** `src/multiplexer/restart_loop_guard.rs:81-105` discards each predecessor older than 60s; `src/main.rs:1303-1319` uses that verdict to auto-resume. A repeating 150s failure cycle never accumulates three boots and keeps restarting the same work.
- **Minimal boundary:** only the persisted restart-interrupted boot classifier and its tests; keep explicit real-message resume and the existing pending markers. Add a maximum-gap policy and bounded retained history; do not redesign the supervisor.
- **RED/GREEN:** `cargo test --lib restart_chain_trips_for_slow_cycles`. Given fresh temp state, call the public guard at times 0, 150, 300, recreating the guard between calls. RED verdicts false/false/false; GREEN false/false/true. A separate gap=301 fixture must reset the chain. Existing fast-cycle case remains a control; deliberately update the old window-only expectation.
- **Local surface:** seed one pending session and the boot-chain fixture, invoke boot recovery through the same decision seam as main with fixed now=300. GREEN zero automatic backend starts, pending retained, then an explicitly routed user event still runs. This also avoids relying on the existing bot-key recovery defect.

All 47 paths eventually fetched. `cron/executions.py` initially failed DNS resolution and was fetched successfully in the next targeted wave; final functions/ledger docs were inspected. No checkout or cached source file was written by the audit scripts.
2. Bounded AST extraction executed the **actual pinned pure predicates** in memory with fixture clocks, not importing/running the Hermes application:
   - `_chain_ending_at([0,150], now=300, gap=300)` plus current boot produced `[0.0,150.0,300.0]`; the explicitly labeled Rust-source-equivalent 60s filter produced `[300.0]` (not a Rust execution).
   - `_retire_expired_oneshot`: age120 -> false; age121 -> true; only fixture ID121 retired.
   - `_marker_is_expired`: age3601 -> true, with expected expired-marker diagnostic.
   The first AST harness attempt failed with `TypeError: required field "lineno" missing from stmt`; adding `ast.fix_missing_locations` corrected the harness and the listed results then executed successfully. This was not an upstream failure.
3. **Delivery-queue semantic caution:** pinned `cron/delivery_queue.py:247-279` terminalizes abandoned `delivering` as unknown and never automatically retries it, whereas `:310-351` leaves never-attempted pending output queued across worker timeout. A successful worker return on deferral is not a Discord receipt. Incorporate this distinction into existing cron C01/C03/C11 contracts: do not implement blind retry of ambiguous sends or ACK a merely queued message. This is mapped work, not a tenth finding.
4. **Continuable cron is optional Discord parity, not excluded as non-Discord.** `cron/scheduler_delivery.py:211-234,276-306,1527-1560` can create/seed a dedicated thread or an in-channel lane. Existing cron C14/sessions F08/F12 own exact lane identity and authoritative continuity; SQLite-only mirror cannot establish OMO history continuity (`src/agent/omo_backend.rs:347-360` sends current input only). Coordinate there; do not count the same continuity defect again or silently replace the requested permanent conversation policy.
5. Source decomposition is extensive: upstream `gateway/run.py` shrank from 23,184 to 5,512 lines, `session.py` from 2,815 to 1,222. Coverage means every assigned file was retrieved, structurally compared and role-classified, with relevant behavior/callers read; it does **not** mean every unassigned extracted module or independent agent implementation was audited. Formatting/docstring changes were not promoted to runtime findings.
6. Existing test source was read where it bears on these deltas. The one-shot lease integration uses unbounded receives; proposed regressions must bound exact signals. Existing restart tests intentionally encode the old short-window semantics. Neither was run or claimed passing.
