### AP04 - repair semantics, not regex quantity

Four independently reproducible classes share detector scope:
- `rm -rf //*`: root regex permits dot-slash groups but not empty slash groups; Never reaches execution. Hermes line 434 explicitly handles repeated slashes. Pure detector RED=None/GREEN=hardline; do not execute.
- `echo "$(reboot)"` and `grep "$(reboot)" file`: masker erases non-inert operands despite storing inert_single_quoted; no payload extractor restores reboot. Direct detector RED=None/GREEN=hardline, while `echo 'reboot'` stays benign. For local surface QA, a temporary executable named reboot only writes a marker; Never must block before it runs. Literal root payloads remain detector-only.
- `python3 -cprint(1)`, `node --eval=process.exit(0)`, `rg --pre ./helper needle file`: attached flags/program-bearing read options are not parsed; no dangerous pattern fires. Hermes `1383-1552` handles these. RED=not dangerous/GREEN=gated; helper QA writes a temp marker and is not invoked before consent. Include benign `python script.py -c` and `bash --norc script.sh` controls (current parser falsely interprets positional/long-option data as execution).
- Terminal joins argv without quoting. `{"program":"rm","args":["-rf","/tmp/a'b"]}` becomes unmatched shell syntax and misses recursive detection (`rm` is not program-bearing malformed fallback); real exec removes that directory. Similarly printf arguments containing a single unmatched quote fail hardline parsing despite being valid argv. Preserve argv ownership, and inspect actual shell payload only when an interpreter owns it.

Scope: security normalize/hardline plus terminal command representation. Test `approval_detector_preserves_executable_semantics`; `cargo test --lib approval_detector_preserves_executable_semantics`. Use actual TerminalTool + rejecting requester on temp `a'b`: RED removed with zero prompts/GREEN untouched and one request. Existing classifier tests remain controls. These are dormant-path defects, not proof of daemon bypass.
